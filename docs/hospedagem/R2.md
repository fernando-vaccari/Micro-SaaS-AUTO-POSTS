# Cloudflare R2 — arquivos privados

R2 armazena mídia; o backend Python, FFmpeg e a voz executam em um host CPU separado. Não é necessário manter o antigo B2 funcionando para usar R2. Os objetos legados B2 preservam o provedor registrado; não há migração automática de arquivos entre fornecedores.

## Configurar

1. No painel Cloudflare, abra R2 e confira as condições de ativação/faturamento da sua conta. Crie bucket **privado**, preferencialmente Standard. Use buckets diferentes para comercial e demo.
2. Em R2 → gerenciamento de tokens/API, crie credenciais S3 de leitura e escrita de objetos, limitadas ao bucket escolhido. Guarde **Access Key ID** e **Secret Access Key**. O token da API Cloudflare não substitui esse par S3.
3. Copie o Account ID e o endpoint S3 exibidos no painel.
4. No gerenciador seguro do host:

```dotenv
STORAGE_BACKEND=r2
R2_ACCOUNT_ID=
R2_BUCKET_NAME=autoposts-media
R2_ENDPOINT=
R2_ACCESS_KEY_ID=
R2_SECRET_ACCESS_KEY=
MEDIA_TTL_HOURS=10
```

R2_ENDPOINT é opcional se R2_ACCOUNT_ID está definido; o código deriva `https://ACCOUNT_ID.r2.cloudflarestorage.com`. Para jurisdição EU, use o endpoint oficial exibido no painel. Região S3 é `auto`; assinatura SigV4, path addressing e TLS verificado. Não habilite acesso público r2.dev para contornar autenticação.

## Testar

Configure GitHub Settings → Secrets and variables → Actions:

- Secrets: R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY.
- Variables: R2_ACCOUNT_ID, R2_BUCKET_NAME; R2_ENDPOINT opcional.

Execute Actions → **Testar armazenamento Cloudflare R2** → Run workflow → branch desta entrega (`feat/voice-photo-studio`). Somente `R2_ROUNDTRIP_OK` confirma upload, HEAD/SHA-256, leitura e exclusão reais. O workflow é manual para evitar operações com credenciais ausentes. Não foram inventadas nem alteradas credenciais do usuário.

O teste pode ser executado no host com `.venv/bin/python -m scripts.test_r2` se as variáveis reais estiverem injetadas de forma segura. Os Secrets GitHub não são automaticamente compartilhados com seu servidor.

## Retenção de 10 horas

Arquivos gerados têm generated_at e media_expires_at persistidos. A limpeza automática passa a removê-los a partir de 10 horas, mesmo com o cliente ativo. Agendamentos e envios em andamento ficam protegidos; após publicação/cancelamento, o arquivo expirado é elegível na próxima rodada. Publicações já feitas no Instagram não são removidas.

O banco conserva somente metadados/histórico/cotas; não contém os bytes dos vídeos. Cache local e objeto R2 são removidos, com outbox durável para repetir falhas. A exclusão só é confirmada quando o provedor confirma ausência. R2 não suporta versionamento S3: o adaptador usa DeleteObject + HEAD, sem listar versões B2.

Fotos originais necessárias às campanhas e gravações autorizadas têm política própria; não são apagadas dez horas depois e quebram a campanha. Vozes podem ser revogadas/excluídas no estúdio. A limpeza exige backend/worker funcionando; se a hospedagem parar, ela será retomada ao voltar. A política não é uma garantia de limite de gastos.

## Plano gratuito e custos

Fonte oficial consultada: https://developers.cloudflare.com/r2/pricing/. Na consulta, Standard tinha franquias de 10 GB-mês, 1 milhão de operações Class A e 10 milhões Class B por mês; egress direto R2 sem tarifa de transferência. Essas cotas não se aplicam da mesma forma a Infrequent Access. Preços/termos podem mudar e excedentes podem gerar cobrança. Confira o painel, configure alertas e dimensione usuários/limites.
